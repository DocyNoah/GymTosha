# PPO 환경 벤치마크 파이프라인

한 환경에서 GymTosha와 Gymnasium이 **같은 평가 성능에 안정적으로 도달하는 데 걸린 시간**을 비교합니다. 모든 PPO 과제에 아래 순서를 적용합니다. 과제마다 목표 보상과 기본 PPO 설정을 정하고, **그룹 안에서는 rollout 배치와 미니배치 크기를 고정**해 병렬화 효과를 비교합니다.

## 1. 과제와 평가 기준 확정

- `env-id`, 환경 버전, 관측·행동 설정, 보상·종료 조건과 episode time limit을 기록합니다. GymTosha와 Gymnasium의 전이가 다르면 그 차이를 명시합니다.
- 같은 PPO 학습기를 사용합니다. 정책망과 가치망의 은닉층은 각각 `256–256–256`으로 고정하고, 전체 rollout 횟수 $U$와 평가 간격을 실행 전에 정합니다. 사용자가 정한 값은 탐색에서 제외합니다. 예를 들어 CartPole의 GAE λ는 `0.99`입니다.
- 과제별 목표 리턴을 미리 정합니다. 학습과 별도의 **Gymnasium 평가 환경**에서 체크포인트마다 독립적으로 시드가 지정된 100개 에피소드를 실행하고 평균과 표준편차를 기록합니다. 평가 정책, 평가 시드, 평가 간격과 달성 조건은 모든 백엔드에서 같게 적용합니다.
- 기본 달성 판정은 평가 평균이 목표 이상인 체크포인트 **5회 연속**입니다. 과제에 맞는 추가 조건은 실행 전에 명시합니다. 예를 들어 CartPole은 평균 475 이상이면서 100개 중 95개 이상이 각각 475 이상이어야 합니다. 마지막 확인이 끝난 시점의 경과 시간과 트랜지션 수를 기록합니다.

## 2. 백엔드 용량과 탐색 장치 확인

- 환경 수는 **기준 {32}, 중간 {256, 512, 1,024}, 대형 {4,096, 8,192, 16,384}**의 세 그룹으로 나눕니다. Gymnasium Async는 32만 확인합니다. Gymnasium Sync, 환경 전용 NumPy 배치 구현이 있으면 그 구현, GymTosha CPU·CUDA·MPS의 eager·compile을 지원 범위에서 확인합니다.
- 각 백엔드와 환경 수에서 초기화, 첫 rollout 수집, PPO 업데이트 한 번을 단독 실행합니다. **60초 이내**에 한 반복을 완료하고 손실이 유한하며 파라미터가 바뀌어야 통과입니다. 시간 초과, 메모리 부족, 미지원은 구분해 기록합니다. 최종 설정의 $T$와 미니배치가 사전 확인과 다르면 그 설정으로 다시 확인합니다.
- 환경과 학습기는 같은 장치에 둡니다. Gymnasium 백엔드는 둘 다 CPU에서 실행합니다. GymTosha 탐색은 필요한 환경 수마다 같은 설정으로 CPU와 CUDA를 단독 측정해 더 빠른 쪽을 사용합니다. 장치 순위는 환경 수에 따라 달라질 수 있습니다.

## 3. 32개에서 기본 PPO 설정 탐색

1. 같은 10개 학습 시드로 후보를 비교합니다. 학습률·스케줄, 할인율, rollout 길이, 미니배치 크기, epoch 수, PPO clip, entropy·value 계수, gradient norm 상한 등에서 한 번에 한 항목만 바꿉니다. 한 항목의 선택값을 적용한 뒤 다음 항목으로 넘어갑니다.
2. 후보 점수는 시드별 **마지막 5개 평가 체크포인트 평균**의 10시드 평균입니다. 체크포인트별로 평가 에피소드 100개의 평균을 먼저 구합니다. 후보 평균과 시드 간 표준편차를 함께 표시하며, 평균이 같으면 표준편차가 작은 후보를 선택합니다. 전체 학습 구간의 에피소드 평균은 진단에 사용합니다.
3. 같은 학습 설정·시드의 완료 기록을 재사용합니다. 원시 평가 기록이 현재 평가 조건과 일치하면 재집계합니다. GPU나 CPU를 공유해 탐색을 병렬로 돌릴 수 있으며, 그 경과 시간은 백엔드 속도 비교에서 제외합니다.

## 4. 그룹별 rollout 배치와 미니배치 선택

기준 그룹은 32개에서 선택한 $T$와 $M$을 재사용합니다. 중간·대형 그룹은 각각 rollout당 수집 슬롯 $B=NT$와 미니배치 크기 $M$을 정합니다. 가장 큰 환경 수 $N_{\max}$에서도 학습에 충분한 rollout 길이가 나오도록, 그 지점에서 검증할 $T$ 후보로 $B=N_{\max}T$를 계산합니다. 각 $B$에 대해 $B$를 나눌 수 있는 몇 가지 $M$을 함께 비교합니다. [Rudin 등, §2.2.1·그림 4](https://arxiv.org/html/2109.11978)

1. 중간 그룹은 **256·1,024개**, 대형 그룹은 **4,096·16,384개**에서 각 $(B,M)$ 후보를 같은 10개 학습 시드로 평가합니다. 후보마다 공통 rollout 횟수까지 학습합니다. 배치가 다른 후보는 총 경험량도 달라지므로 유효 트랜지션 대비 평가 곡선도 확인합니다.
2. 양 끝의 목표 달성률과 마지막 5개 평가 평균에 적용할 기준을 과제별로 미리 정합니다. 두 지점 모두 기준을 만족하는 조합을 고르고, 학습 성능이 비슷하면 단독 측정의 목표 도달 시간을 비교합니다.
3. 선택한 $(B,M)$을 **512개와 8,192개**에서도 각각 같은 10개 시드로 검증합니다. 확정한 설정은 그룹 내 모든 환경 수와 해당 설정을 실행할 수 있는 백엔드에 적용합니다.

| 항목 | 본 비교의 규칙 |
| --- | --- |
| rollout당 수집 슬롯 $B=NT$, 미니배치 크기 $M$ | 그룹별로 선택하고 그룹 안에서 고정 |
| 환경당 rollout 길이 $T$ | 각 환경 수 $N$에서 $B/N$ |
| epoch당 미니배치 개수 $K$, 전체 수집 슬롯 예산 $S$ | 각각 $B/M$, $UB$로 그룹 안에서 고정 |
| PPO epoch 수 $E$, 전체 rollout 횟수 $U$, 학습률·스케줄, 나머지 PPO 설정 | 세 그룹 공통 |
| 예정 optimizer 호출 횟수 | rollout당 $EK$, 전체 $UEK$로 그룹 안에서 고정 |

예를 들어 중간 그룹에서 $B=65{,}536$이면 환경 수 256·512·1,024개에 각각 $T=256,128,64$를 씁니다. $B$가 그룹의 모든 $N$과 선택한 $M$으로 나누어떨어지게 설정합니다. 리셋 전용 슬롯을 건너뛰는 백엔드는 수집 슬롯·유효 트랜지션·실제 optimizer 호출 수를 따로 기록합니다.

실행 가능한 공통 배치에서 큰 $N$의 짧은 $T$가 학습 기준을 충족하지 못하면, 보조 실험으로 그룹 내 $T$와 $K$를 고정하고 $M=NT/K$를 적용합니다. 이 경우 예정 optimizer 호출 횟수는 같고 총 수집 슬롯은 $N$에 비례합니다. 보조 실험의 배치 규칙과 결과를 기본 비교와 구분해 표시합니다.

## 5. 고정 길이 학습과 월타임 비교

- 통과한 백엔드·환경 수 조합마다 탐색과 겹치지 않는 **20개 학습 시드**를 실행합니다. 비교 조건 간에는 같은 시드를 대응시키고, 월타임은 자원을 공유하지 않는 단독 실행에서 측정합니다. 가능하면 같은 호스트에서 비교하고, 하드웨어와 컴파일 캐시 상태를 기록합니다.
- 평가 간격은 공통 rollout 횟수 단위로 정합니다. 목표를 확인해도 모든 실행을 $U$회까지 학습합니다. 목표 도달 월타임은 환경 생성 시작부터 확인 평가 종료까지 재며, 컴파일·워밍업, 수집과 PPO 업데이트 시간을 포함합니다. 트랜지션 대비 곡선에는 유효 트랜지션 수를 사용합니다.
- **같은 환경 수 비교**에서는 같은 PPO 설정의 백엔드 차이를 봅니다. **같은 그룹 안의 환경 수 비교**에서는 같은 수집 예산과 예정 optimizer 호출 횟수에서 $N$과 $T$의 배분을 바꾼 효과를 봅니다.
- **백엔드별 최적 환경 수 비교**에서는 20개 시드 모두 목표를 달성한 환경 수 중 평균 도달 시간이 가장 짧은 값을 고릅니다. 그룹을 넘는 비교에는 설정과 목표 도달까지의 실제 트랜지션 수, optimizer 호출 수도 함께 표시합니다. 모두 달성한 구성이 없으면 달성률과 최종 평가 점수를 표시합니다. 미달 시드의 도달 시간은 비워 두고, 해당 비교의 가속 배율은 산출하지 않습니다.

## 6. 결과 기록과 시각화

- 원시 결과에 그룹과 배치 규칙, 실행별 설정, 학습·평가 시드, 환경 수, 백엔드·장치, 평가 에피소드 리턴, 체크포인트 시간·스텝·optimizer 호출 수, 도달 여부와 실패 사유를 저장합니다. 환경 생성·컴파일·수집·업데이트·평가 시간도 따로 남깁니다.
- 탐색 후보별 **마지막 5개 평가 평균과 시드 간 표준편차**, 환경 수·백엔드별 **달성률과 도달 시간 히트맵**, **월타임 대비 및 유효 트랜지션 대비 학습 곡선**을 제공합니다. 곡선은 체크포인트별 평가 평균과 시드 간 표준편차를 표시합니다.
- 백엔드별 최적 환경 수 비교에는 20개 시드의 개별 도달 시간, 평균·표준편차, 최종 평가 점수를 표시합니다. 용량 검증 실패, 학습 목표 미달, 아직 실행하지 않은 조건을 구분합니다.

이 문서는 신규 PPO 비교에 적용할 절차입니다. 기존 CartPole 결과와 재현 명령은 [이전 실험 명세](CARTPOLE_STUDY.md)에 있습니다.

## RTX 3090에서 CartPole 실행

```bash
uv sync --frozen --extra benchmark
uv run --no-sync python -m gymtosha.benchmarks.study_grouped \
  --baseline benchmarks/results/cartpole-study/scaling/selected.json \
  --output outputs/cartpole-grouped --devices cpu cuda --parallel-trials 8
```

같은 출력 경로로 재실행하면 완료된 탐색·검증·비교 기록을 재사용합니다. 그룹별 선택과
실패 사유는 `groups/`, 용량 결과는 `capacity-screening/`과 `capacity-selected/`,
표와 그림은 `index.html`에서 확인합니다. CartPole 그룹 탐색은 양 끝에서 모두
10개 시드가 안정적으로 도달하고 마지막 5개 평가 평균이 475점 이상인 후보를 선택합니다.
두 끝점 각각에서 최고점과 5점 이내인 후보의 단독 실행 시간을 비교합니다.
