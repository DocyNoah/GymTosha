# PPO 환경 벤치마크 파이프라인

GymTosha와 Gymnasium에 같은 양의 학습 경험을 주고, 같은 평가 성능에 안정적으로 도달하는 데 걸린 시간을 비교합니다. CartPole은 환경 수 전체에 단일 수집 예산을 적용합니다.

## 1. 과제와 평가 기준

- 환경 ID·버전, 관측·행동, 보상과 종료 조건을 기록합니다. 환경 구현이 다르면 차이를 명시합니다.
- PPO 학습기는 공통으로 사용하고 정책망과 가치망은 각각 `256–256–256`으로 구성합니다. CartPole은 GAE λ `0.99`와 기존 학습률·스케줄을 사용합니다.
- 별도 Gymnasium 평가 환경에서 체크포인트당 100개 에피소드를 실행합니다. CartPole은 평균 보상이 475 이상이고, 100개 중 95개 이상이 475 이상인 평가를 **5회 연속** 통과했을 때 도달로 판정합니다. 마지막 확인 시점의 월타임, 유효 트랜지션과 optimizer 호출 수를 기록합니다.

## 2. 공통 학습 예산

환경 수 $N$, 환경당 rollout 길이 $T$, rollout 횟수 $U$, 미니배치 크기 $M$, PPO epoch 수 $E$로 표기합니다.

| 단계 | 고정 | 변경 |
| --- | --- | --- |
| rollout 길이 탐색 | $N,S,M,E$, 학습률과 평가 시점 | $T$, $U=S/(NT)$ |
| 환경 수와 백엔드 비교 | 선택한 $T,S,M,E$, 학습률과 평가 시점 | $N$, $U=S/(NT)$ |

두 단계의 총 수집 예산은 모두 $S=UNT$입니다. $NT$는 $M$으로 나누어떨어져야 하며, 전체 optimizer 호출 수는 $ES/M$입니다. 학습률은 optimizer 호출 순서에 따라 같은 비율로 줄입니다. 같은 예산에서도 $N$이나 $T$가 달라지면 한 번에 모으는 양과 정책을 갱신하는 빈도가 달라집니다.

평가는 모든 구성에서 같은 누적 수집량에 실시합니다. 평가 간격은 비교할 rollout 배치들의 공배수로 정해 평가 전에 PPO 업데이트가 끝나게 합니다. 목표를 확인한 실행도 $S$까지 학습합니다. 최댓값의 $NT$에서도 최소 16회 정책 갱신과 16개 학습 후 평가 시점을 확보합니다.

Gymnasium의 CartPole 전용 NumPy 백엔드에서는 종료한 행을 같은 스텝에 리셋합니다. 원래 벡터 물리 계산과 리셋 분포를 사용하면서 종료 관측을 보존하므로, 다음 수집 슬롯도 학습에 쓸 수 있습니다. 모든 비교에서 수집 슬롯, 유효 트랜지션, 실제 optimizer 호출 수를 따로 기록합니다.

## 3. rollout 길이 재탐색

CartPole은 RTX 3090에서 $N=1{,}024$로 고정하고 $T=16,32,64,128,256,512$를 같은 10개 시드로 비교합니다. 이전 512 선택은 rollout 횟수를 고정한 탐색에서 나왔고, 후보마다 경험량이 달랐습니다. 새 설계에서는 512도 같은 예산에서 다시 평가합니다.

| 항목 | CartPole 설정 |
| --- | ---: |
| 총 트랜지션 $S$ | 134,217,728 |
| 미니배치 크기 $M$ | 512 |
| PPO epoch 수 $E$ | 4 |
| 공통 평가 간격 | 8,388,608 트랜지션 |
| 예정 optimizer 호출 수 | 1,048,576 |

$S$는 최대 구성인 $16{,}384\times512$의 rollout 16회분입니다. $M=512$는 가장 작은 $32\times16$ 수집 배치부터 모든 후보를 나눌 수 있습니다. 탐색의 월타임은 각 시드를 단독 실행해 측정합니다.

후보마다 마지막 5개 평가의 시드별 평균과 시드 간 표준편차를 기록합니다. 10개 시드가 모두 안정적으로 도달하고 마지막 평가 평균이 475 이상인 후보 중, 최고 평균과 5점 이내인 후보를 비교해 목표 도달 시간이 가장 짧은 $T$를 선택합니다. 모든 시드가 도달한 후보가 없으면 가장 높은 마지막 평가 평균의 $T$를 선택하고 그 사실을 기록합니다.

## 4. 백엔드 용량과 최종 비교

- 환경 수는 **32, 256, 512, 1,024, 4,096, 8,192, 16,384**입니다. 각 환경 수에 하나의 $T$를 적용합니다. Async는 32개까지만 비교합니다.
- 실제 설정으로 환경 초기화부터 PPO 업데이트 한 번까지 60초 이내에 완료해야 통과입니다. 용량 실패는 시간 초과, 메모리 부족, 미지원 등 원인별로 기록합니다.
- 통과한 조건마다 탐색과 겹치지 않는 **20개 시드**로 단독 실행합니다. Gymnasium과 GymTosha CPU·CUDA는 RTX 3090 호스트에서, GymTosha MPS는 Apple 호스트에서 측정합니다. 호스트와 eager·compile 구성을 결과에 표시합니다.
- 목표 도달 월타임은 환경 생성부터 컴파일·워밍업, 학습, 확인 평가 종료까지입니다. 같은 환경 수의 백엔드, 백엔드 안의 환경 수, 백엔드별 최적 환경 수를 비교합니다. 20개 시드가 모두 도달한 조건끼리 평균 도달 시간을 비교합니다. 미달 시드가 있는 조건은 달성률과 마지막 평가 점수를 보고합니다.

## 5. 결과 기록과 실행

실행별 설정, 시드, 체크포인트별 100개 평가 리턴과 평균·표준편차를 보존합니다. 결과 화면에는 목표 달성률, 도달 시간, 월타임 및 유효 트랜지션에 따른 학습 곡선, 백엔드별 최적 환경 수를 표시합니다.

```bash
uv sync --frozen --extra benchmark
uv run --no-sync python -m gymtosha.benchmarks.study_fixed_budget \
  --baseline benchmarks/results/cartpole-study/scaling/selected.json \
  --output outputs/cartpole-fixed-budget-3090 --devices cpu cuda --tune-envs 1024
```

MPS에서는 RTX 3090 실행이 생성한 `selected.json`을 별도의 출력 경로로 복사하고 `--devices mps --compare-only`를 사용합니다. 같은 프로토콜과 출력 경로로 재실행하면 완료 기록을 재사용합니다. 이전 그룹별 비교의 재현 명령은 [이전 CartPole 실험 명세](CARTPOLE_STUDY.md)에 있습니다.
