# CartPole PPO 실험 명세

## 고정 조건

- 과제는 `CartPole-v1`, 알고리즘은 PPO입니다.
- 정책망과 가치망은 각각 256–256–256 은닉층을 사용합니다. 활성화는 Tanh입니다.
- AsyncVectorEnv의 환경 수 상한은 32입니다.
- SyncVectorEnv, CartPoleVectorEnv, GymTosha는 4,096개에서 시작해 성공하면 두 배, 실패하면 절반으로 탐색합니다.
- 시스템 파일 한도, 메모리 한도와 프로세스 시작 방식을 올리거나 우회하지 않습니다.
- CUDA는 RTX 3090 서버, MPS는 Apple M3 Max에서 실행합니다. 장치 간 결과에는 호스트 차이를 명시합니다.

## 순서

1. 백엔드별 실행 가능한 환경 수를 확인합니다.
2. GymTosha CUDA compiled, 환경 32개에서 한 파라미터씩 탐색합니다.
3. 각 후보를 동일한 10개 학습 시드로 측정하고 평균·표준편차와 실패 여부를 저장합니다.
4. 선택한 값을 고정한 뒤 다음 파라미터를 탐색합니다.
5. 환경 수를 64, 128, 256 등 두 배로 늘리며 이전 선택값을 초기값으로 사용합니다.
6. 백엔드별 가능한 환경 수에서 같은 설정을 적용해 독립된 20개 시드로 비교합니다.
7. 각 백엔드의 가장 효율적인 환경 수를 선택해 최종 비교합니다.

## 백엔드

| 백엔드 | 실행 장치 | 환경 구현 |
| --- | --- | --- |
| Gymnasium AsyncVectorEnv | CPU | 환경별 워커, 최대 32개 |
| Gymnasium SyncVectorEnv | CPU | 순차 실행 |
| Gymnasium CartPoleVectorEnv | CPU | 전용 NumPy 배치 |
| GymTosha eager / compiled | CPU | PyTorch 배치 |
| GymTosha eager / compiled | CUDA | PyTorch 배치 |
| GymTosha eager / compiled | MPS | PyTorch 배치 |

## 파라미터 후보안

다른 파라미터를 고정한 상태에서 아래 순서로 한 축씩 탐색합니다.
PPO의 수집 버퍼 크기는 환경 수와 rollout 길이의 곱으로 정합니다.

| 파라미터 | 후보 |
| --- | --- |
| 학습률 | 0.01, 0.003, 0.001, 0.0003, 0.0001 |
| gamma | 0.998, 0.995, 0.99, 0.98, 0.95 |
| rollout 길이 | 16, 32, 64, 128, 256, 512 |
| 미니배치 크기 | 32, 64, 128, 256, 512, 1024, 2048 및 수집 배치 이내의 두 배 값 |
| 업데이트 epoch | 2, 4, 8, 10 |
| GAE lambda | 0.90, 0.95, 0.97, 0.99 |
| PPO clip | 0.10, 0.20, 0.30 |
| entropy coefficient | 0, 0.001, 0.01, 0.03 |
| value coefficient | 0.25, 0.5, 1.0 |
| gradient norm 상한 | 0.5, 1.0, 2.0 |
| Adam epsilon | 1e-8, 1e-5 |
| 학습률 일정 | constant, linear |

## 통계와 평가

탐색 셀은 학습 시드 10개, 최종 백엔드 비교 셀은 학습 시드 20개를 포함해야 합니다. 일부 완료된 셀의 평균을
완료된 비교처럼 표시하지 않습니다. 실패한 학습을 통계에서 제외하지 않습니다.
목표 점수는 별도 Gymnasium 평가의 평균 475이며, 아래 안정적 도달 판정을 적용합니다.
탐색 시드와 최종 비교 시드를 분리하며 백엔드 간 같은 시드를 대응시킵니다.

목표 도달 시간에는 환경 생성, 컴파일, 학습과 평가를 포함합니다.
생성·컴파일·수집·업데이트 시간도 따로 보관합니다.
기록은 후보별 JSON, 시드별 CSV, 선택 이력과 실패 사유를 포함합니다.

## 시각화

- 한 파라미터 탐색마다 후보별 안정적 도달 수와 학습 에피소드 보상 평균·표준편차를 표시합니다.
- 환경 수와 파라미터 값에 따른 결과는 히트맵으로 표시합니다.
- 환경 수별 선택값 변화와 백엔드별 학습 곡선을 표시합니다.
- 백엔드별 최적 환경 수 비교에는 원시 20개 시드와 평균·표준편차를 함께 표시합니다.
- 시드 수, 하드웨어, 예산과 실패 사유를 결과에서 직접 확인할 수 있게 합니다.

최적 환경 수의 평가 곡선은 체크포인트별 20개 시드의 평가 보상 평균과 표본
표준편차를 표시합니다. 가로축은 수집 슬롯 수와 체크포인트별 평균 경과 시간입니다.
`search-seeds.csv`는 후보별 시드 보상, `comparison-seeds.csv`는 최종 비교의 시드별
보상·경과 시간·목표 도달 시간과 스텝을 담습니다.

## 확정된 학습 길이와 선택 기준

최대 환경 수 검증은 PPO rollout 수집과 학습 업데이트까지 포함합니다.
정책망과 가치망 모두 256–256–256, rollout 128스텝을 수집하고 1 epoch,
미니배치 4개로 업데이트하는 한 반복을 실행해 유한한 손실과 파라미터 변경을 확인합니다.
용량 검증은 기능 확인이며 평균·표준편차를 보고하는 학습 실험과 구분합니다.

탐색과 최종 비교는 고정된 rollout 업데이트 반복 횟수까지 학습합니다.
환경 수가 두 배면 총 transition 수도 두 배입니다. 환경 수만 바뀔 때는 미니배치 크기도
비례해서 늘려 미니배치 개수와 optimizer 업데이트 횟수를 유지합니다.
rollout 길이, epoch와 미니배치 크기를 직접 탐색하면 이에 따른 파생 수량을 기록합니다.
목표 점수 달성 뒤에도 학습을 계속하고 최초 확인 스텝과 시간은 별도로 보존합니다.

하이퍼파라미터 선택 통계는 고정 학습 구간 전체에서 완료된 에피소드 보상의 평균입니다.
각 시드의 에피소드 보상 평균을 먼저 계산하고, 탐색 시드 10개의 평균과 표본 표준편차를 보고합니다.
가장 높은 평균 보상을 선택하며 동률이면 표준편차를 비교합니다.
목표 달성률과 최초 도달 시간은 별도 참고 지표로 보존합니다.

## 안정적 도달 판정

CartPole의 새 실험은 학습과 별개의 평가 환경 100개를 사용합니다.
다음 두 조건을 연속 5회 만족한 다섯 번째 평가 종료 시점에 도달했다고 기록합니다.

- 평균 에피소드 보상 475 이상
- 100개 중 95개 이상의 에피소드 보상 475 이상

도달 후에도 고정된 rollout 업데이트 반복 횟수까지 학습합니다. 이후 점수가 낮아지더라도
최초 안정 도달 시점과 후속 학습 곡선을 모두 보존합니다.
일반 벤치마크 CLI에서 이 판정은 `--fixed-length --confirmations 5 --min-episode-success-rate 0.95`로 지정합니다.

## 환경 수 검증의 시간 상한

환경 생성·수집·PPO 업데이트를 포함한 한 번의 검증을 60초 이내로 제한합니다.
60초가 지나면 해당 환경 수는 사용 가능한 용량에서 제외하고 절반 크기를 적용합니다.
60초를 넘겼던 과거 실행은 원래 결과와 시간을 보존하면서 이 기준에서는 실패로 분류합니다.
시스템 자원 한도를 늘리거나 더 오래 기다려 통과시키지 않습니다.

## 실행 계획

각 실행은 rollout 업데이트 64회까지 진행합니다. 기본 rollout 길이 128, 환경 32개이면
총 262,144 sampling slot이며, 환경 수가 두 배가 되면 총 slot 수도 두 배입니다.
Gymnasium NEXT_STEP 초기화 slot은 손실에서 제외하고 유효 transition 수도 따로 기록합니다.

32개 환경에서는 후보 전체를 탐색합니다. 더 큰 환경 수에서는 이전 선택값과 인접 후보로
시작하고, 경계 후보가 가장 좋으면 범위를 넓혀 다시 확인합니다. 한 번에 한 파라미터만
바꾸며, 동일 설정의 10개 시드 결과는 재사용합니다.
탐색 시드는 1–10, 최종 비교 시드는 1001–1020입니다. 평가는 4 rollout 업데이트마다 수행합니다.

```bash
uv run --extra benchmark python -m gymtosha.benchmarks.study tune \
  --device cuda --min-envs 32 --max-envs 65536 --parallel-trials 16 \
  --output outputs/cartpole-study-full
uv run --extra benchmark python -m gymtosha.benchmarks.study compare \
  --presets outputs/cartpole-study-full/selected.json \
  --capacity benchmarks/results/cartpole-study/capacity/summary.json \
  --devices cpu cuda --output outputs/cartpole-study-full
```

`index.html`은 환경 수와 파라미터를 선택하는 오프라인 결과 화면입니다.
`search/`에는 후보별 10시드 통계와 그림, `trials/`에는 설정·진행·평가 원시 기록이 있습니다.
완료된 실행은 설정과 학습 소스·런타임이 일치할 때 재개 과정에서 재사용합니다.

## 최종 백엔드별 환경 수 선택

20개 시드 모두 안정적 도달에 성공한 환경 수가 있으면 평균 안정적 도달 시간이 가장
짧은 크기를 선택합니다. 모든 환경 수에 미달성 시드가 있으면 평균 학습 에피소드 보상이
가장 높은 크기를 표시하되, 안정적 도달을 확인한 설정과 구분합니다.
`best-backends.json`에 선택 기준과 환경 수, 평균·표준편차를 함께 기록합니다.
`index.html`에서 파라미터별 후보, 환경 수별 히트맵, 선택값 변화와 최종 비교를 확인합니다.

탐색 학습에도 초기화와 각 rollout 수집에 60초 제한을 적용합니다. 제한 초과는 해당
후보의 실패로 보존합니다. 고정 길이 학습 전체의 경과 시간은 60초로 자르지 않습니다.
수집 시간, 업데이트 시간과 학습기 초기화 시간은 `phase_seconds`에 별도로 기록합니다.

## 탐색 병렬 실행

하이퍼파라미터 탐색은 기본 최대 16개 실험을 동시에 실행합니다. `--parallel-trials`로
1–32개를 지정할 수 있습니다. 각 실험은 독립된 프로세스와 시드를 사용합니다.
가용 장치 메모리와 rollout·미니배치 크기의 예상 사용량에 따라 동시 실행 수를 줄입니다.
호스트 RAM도 제한에 포함합니다. 가용 RAM의 70% 이내에서 컴파일 워커당 2.5GiB를
예약합니다. 3090 서버에서는 워커와 컴파일러가 합쳐 약 2.2GiB씩 사용했습니다.
예상치보다 큰 단일 실험은 단독 실행으로 실제 성공 여부를 확인합니다.

GPU 공유 중인 탐색 결과는 보상 통계와 안정적 도달 수에 사용합니다. 경과 시간은 원시
기록에 남기되 시간 평균·표준편차와 후보 순위에서는 제외합니다. 이전 단독 탐색의 완료된
시드는 같은 설정·학습 코드·런타임이면 재사용합니다. 최종 백엔드 속도 비교는 별도 시드로
한 번에 한 실험씩 실행합니다.

탐색 시드 수는 사용자 요청에 따라 20개에서 10개로 변경했습니다. 이전 실행의 시드
1–10 원시 기록을 재사용하며, 후보 통계와 선택값은 10개 기준으로 다시 계산합니다.
