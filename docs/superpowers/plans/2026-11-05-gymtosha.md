# GymTosha Implementation Plan

> Execute inline with the executing-plans skill. Use tests before implementation.

**Goal** Build batched PyTorch environments and measured learning-speed graphs.

**Architecture** One state tensor per batch, device-local random streams and
masked reset. Shared learner adapters isolate Gymnasium transfers from native
tensor execution. The same algorithms run on both backends.

**Tech Stack** Python 3.12, uv, Ruff, PyTorch, Gymnasium, pytest, matplotlib.

**Spec** docs/superpowers/specs/2026-11-05-gymtosha-design.md

## Global constraints

- No loop over individual environments in simulation.
- No host transfers or tensor-to-Python scalar extraction in the native step.
- Clearly label experimental LunarLander physics and measured hardware.
- Commit incremental working deliverables on codex/initial-batched-envs.

## Review focus

Partial resets preserve active rows. Truncations bootstrap terminal values.
Random streams remain independent of learner sampling. Compile includes reset
without graph breaks. Comparison budgets and update counts match across backends.
